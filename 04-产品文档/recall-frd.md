## 1. 引言

### 1.1 文档目的

本文档将 PRD 中的产品需求细化为**可执行的功能级需求**，逐条明确每个功能的：功能描述、触发条件、前置/后置条件、业务规则、界面与交互细节、字段定义、异常处理与验收标准，作为开发、测试与验收的**唯一功能依据**。

### 1.2 术语与缩写

| 术语 | 说明 |
|---|---|
| 错题（Mistake） | 用户录入的一条错题记录，含题目、学科、知识点、解析、掌握度等 |
| 错题本（Category） | 学科/自定义分类容器，用于组织错题 |
| 视觉识别（OCR/VL） | 对图片调用多模态模型识别题目文字、学科、知识点、解析 |
| 复习会话（Review Session） | 用户在一次"开始复习"中逐题作答的过程 |
| 自评（Self Rating） | 复习后用户对掌握程度打分：陌生 1 / 模糊 3 / 掌握 5 |
| Provider | 模型供应商（DeepSeek / 硅基流动 / 通义千问） |
| 图片即题目 | 拍照/截图录入的错题，卡片题目区直接展示原图，不做 OCR 文字展示 |

### 1.3 范围

- **In**：FR-01~16（与 PRD 一致）全部功能需求。
- **Out**：账号体系、云同步、班级协作、移动端原生 App、支付会员（后续版本）。

## 2. 产品概述

Recall 面向学生群体，解决"错题录入繁琐、整理无章、复习盲目、解析缺失、效果无感"五大痛点。核心价值闭环：**四种方式快速录入 → AI 自动识别归档 → SM-2 智能复习（含 AI 出题与批改）→ 数据看板反馈 → 导出沉淀**。

| 页面 | 职责 |
|---|---|
| 错题集 | 录入入口 + 错题管理 + 复习入口（核心页） |
| AI 答疑 | 多轮对话学习 + 一键加入错题本 |
| 数据看板 | 学习趋势与掌握度可视化（只读） |
| 帮助中心 | FAQ 与使用引导 |

## 4. 功能需求详情

> 每个功能按统一模板：**功能描述 / 触发条件 / 前置条件 / 业务规则 / 界面交互 / 字段定义 / 异常处理 / 验收标准**。

### FR-01 拍照录入

**功能描述**：用户通过摄像头拍照或选择相册图片，上传后由 AI 视觉模型自动识别题目内容、学科、知识点并生成解析，一键归档到错题本。

**触发条件**：错题集 → 操作栏「录入」→ 录入引导页 → 选择「拍照录入」。

**前置条件**：浏览器支持 `input[type=file][capture]` 或文件选择；网络可达（识别需调 AI）。

**业务规则**：
- R-1.1 支持三种取图方式：打开摄像头（`capture=environment`）、从相册选择、拖拽图片到上传区；
- R-1.2 图片格式 JPG/PNG；大小 ≤ 10MB；
- R-1.3 **图片即题目**：识别出的 OCR 文本仅内部参考，卡片题目区直接展示原图；
- R-1.4 识别结果自动判定学科（8 科之一）与知识点，生成解析后归档。

**界面交互**：
| 步骤 | 交互 |
|---|---|
| 1 | 展示上传区：虚线框 +「打开摄像头拍照」「从相册选择」两个按钮 + 拖拽提示 |
| 2 | 图片预览显示（缩略图居中，可点击重选） |
| 3 | 点击「AI 识别并录入」→ 按钮变「AI 视觉识别中…」禁用（防重复提交） |
| 4 | 识别成功 → toast「已识别：数学 · 导数极值问题」→ 自动跳转错题集，新卡片出现在列表顶部 |
| 5 | 识别失败 → toast「AI 视觉识别失败，请重试或改用文本录入」 |

**字段定义**：`image_base64`（图片 dataURL）、`subject`（AI 判定）、`knowledge_point`、`question`（内部 OCR 文本，可空）、`analysis`、`source='拍照录入'`、`mastery_level=0`、`review_count=0`。

**异常处理**：
- 未选图点击识别 → toast「请先拍照或选择图片」；
- 摄像头不可用（桌面/非 https）→ 自动回退文件选择器；
- 识别超时（>10s）→ 提示重试或转文本录入（NFR-03）。

**验收标准**：AC-01 拍照录入 2–3s 内完成识别，自动归档正确学科，卡片显示原图 + 真实 AI 解析，无 OCR 文字冗余。

### FR-02 截图录入

**功能描述**：用户通过粘贴（Ctrl+V）、拖拽或选择本地文件上传截图，识别流程与拍照一致。

**触发条件**：录入引导页 → 选择「截图录入」。

**前置条件**：剪贴板有图片 / 本地有图片文件。

**业务规则**：
- R-2.1 支持粘贴、拖拽、文件选择三种入口；
- R-2.2 全局 `paste` 事件监听，仅当录入面板可见时生效，避免误触；
- R-2.3 识别与归档逻辑复用 FR-01（同一 `ocrAndAnalyze`）。

**界面交互**：同 FR-01；上传区文案「在此区域粘贴截图（Ctrl+V）」。

**字段定义**：同 FR-01，`source='截图录入'`。

**异常处理**：粘贴非图片内容 → 忽略且不报错；无图点击识别 → toast「请先选择/粘贴/拖拽图片」。

**验收标准**：AC-01（截图分支）粘贴/拖拽后自动识别归档。

---

### FR-03 文本录入

**功能描述**：用户输入或粘贴题目文字，AI 自动判断学科、知识点并生成解析，无需手动选学科。

**触发条件**：录入引导页 → 选择「文本录入」。

**前置条件**：题目文字非空。

**业务规则**：
- R-3.1 学科由 AI 自动判断（不提供手动下拉）；
- R-3.2 题目为空不允许提交（输入框标红 + toast）；
- R-3.3 知识点/解析由 AI 生成，返回固定三行格式后正则提取。

**界面交互**：
| 步骤 | 交互 |
|---|---|
| 1 | 展示题目 textarea（placeholder「输入或粘贴题目，AI 将自动识别学科与知识点」） |
| 2 | 点击「AI 识别并保存」→ 按钮 loading「AI 分析中…」 |
| 3 | 成功 → toast「已识别：数学 · 导数应用」→ 跳转错题集归档 |
| 4 | 失败 → toast 提示，输入内容保留不丢失 |

**字段定义**：`question`（必填）、`subject/knowledge_point/analysis`（AI 生成）、`source='文本录入'`。

**异常处理**：AI 分析失败 → 降级为本地规则匹配学科（关键词），解析用兜底文案，卡片仍可归档（NFR-11）。

**验收标准**：AC-02 文本录入提交后 AI 判学科+知识点+解析，卡片置顶且分类计数 +1。

### FR-04 对话录入

**功能描述**：用户通过与 AI 对话描述错题，AI 引导收集信息并确认后归档生成错题。

**触发条件**：录入引导页 → 选择「对话录入」。

**前置条件**：描述文本非空（提供默认示例）。

**业务规则**：
- R-4.1 界面展示模拟对话示例（AI 引导 → 用户描述 → AI 确认）；
- R-4.2 用户补充描述后点击「确认录入错题本」，以描述内容生成错题；
- R-4.3 学科/知识点由 AI 从描述中判定，未命中用默认「数学 · 待归类」。

**界面交互**：聊天式示例气泡 + 描述输入框（必填，placeholder 含示例「如：在顶点坐标处常出错」）+ 确认按钮。

**字段定义**：`question` = 描述内容（为空用默认「二次函数求最值问题」）、`source='对话录入'`。

**异常处理**：描述为空 → 输入框标红提示。

**验收标准**：AC-02（对话分支）提交后生成基于用户描述的错题并归档。

### FR-05 错题本管理

**功能描述**：侧栏展示学科分类与自定义错题本，支持新建、删除、选中筛选，计数实时联动。

**触发条件**：错题集页左侧栏常驻显示。

**业务规则**：
- R-5.1 内置 8 学科（数学/物理/英语/化学/生物/语文/历史/地理）+「全部错题」聚合项；
- R-5.2 「全部错题」受保护，不可删除；
- R-5.3 自定义错题本可新建（输入名称，自动分配配色圆点）、可删除（hover 显示 ×）；
- R-5.4 每个分类显示错题计数；新增/删除错题、编辑改学科后计数实时重算（R4）；
- R-5.5 选中分类仅展示该分类下错题；删除当前选中分类回退「全部错题」。

**界面交互**：
| 步骤 | 交互 |
|---|---|
| 1 | 列表项：配色圆点 + 名称 + 计数 |
| 2 | 点击分类 → 高亮选中态 → 右侧列表过滤 |
| 3 | 「+ 新建错题本」→ 展开内联输入框 →「添加」或回车确认 /「取消」收起 |
| 4 | hover 分类 → 显示「×」删除按钮（全部错题除外） |

**字段定义**：`category {id, name, color, is_default}`。

**异常处理**：重名分类 → 允许（不强制唯一）；删除分类时该分类下错题保留并回退「全部错题」。

**验收标准**：AC-03 分类筛选/新建/删除计数联动正确。

### FR-06 错题列表

**功能描述**：主区以卡片形式展示错题，支持筛选、搜索、展开解析、编辑、删除。

**触发条件**：错题集页主区。

**业务规则**：
- R-6.1 卡片字段：学科标签（彩色）、知识点标签、来源、复习次数、题目（文字或**图片即题目**）、AI 解析（默认折叠）、操作按钮（AI解析/编辑/删除）；
- R-6.2 关键词搜索：匹配卡片全文（题目/知识点/来源等），实时过滤；
- R-6.3 分类筛选与搜索叠加生效（AND 关系）；
- R-6.4 删除错题：卡片移除、分类计数 −1、「全部错题」总数 −1、看板同步刷新；
- R-6.5 某分类下无卡片时显示空状态「该分类下暂无错题」。

**界面交互**：
| 步骤 | 交互 |
|---|---|
| 1 | 操作栏：导出 / 录入 / 开始复习（主按钮）+ 搜索框 / 筛选 |
| 2 | 卡片「AI解析」按钮 → 切换解析区折叠态（展开/收起），文案同步「展开 AI 解析/收起 AI 解析」 |
| 3 | 删除按钮 → 立即移除 + toast「已删除该错题」 |
| 4 | 搜索框输入 → 实时过滤（防抖 200ms 可选） |

**字段定义**：卡片 DOM 关联 `data-subject`（学科 key），用于筛选与看板统计。

**异常处理**：搜索无结果 → 显示空状态（不报错）；图片卡片搜索时按文本内容匹配。

**验收标准**：AC-03 筛选/搜索正确；卡片字段齐全（FR-06 全字段）。

### FR-07 一键复习

**功能描述**：用户选择可见错题进入复习会话，AI 为每道题生成 ABCD 四选项，用户作答后判分并展示解析，自评后写回掌握度。

**触发条件**：错题集 → 操作栏「开始复习」→ 列表视图 →「开始复习」。

**前置条件**：至少 1 道可见错题（最多取 10 道）。

**业务规则**：
- R-7.1 出题：AI 按严格 JSON 返回 `{options[4], correct, explanation}`，1 对 3 错；
- R-7.2 出题失败降级（R5）：跳过选择题，直接展示解析 + 自评，不阻断流程；
- R-7.3 答题判分：选中正确项 → 绿色高亮 +「✓ 答对了」；选中错误项 → 红色高亮 + 正确答案标绿 +「✗ 答错了，正确答案是 X」；
- R-7.4 答完显示自评（陌生1/模糊3/掌握5），自评后该题复习次数 +1、`mastery_level` 写回；
- R-7.5 中途可「退出复习」，已答题进度保留，看板同步；
- R-7.6 全部完成显示总结：答对/错统计 + 陌生/模糊/掌握分布 + 平均掌握度。

**界面交互**：
| 阶段 | 交互 |
|---|---|
| 列表 | 展示今日计划题目（序号+摘要+待复习徽章） |
| 出题中 | 全屏 loading「📝 AI 正在出题中… 为每道题生成 4 个选项与解析（约需 5-10 秒）」 |
| 答题 | 进度条（已答绿/当前紫）+ 题卡 + A/B/C/D 四选项（2 列网格，圆字母徽章）+ 解析（默认展开） |
| 判分 | 选项禁用、正确项变绿、错选项变红、反馈框（绿/红） |
| 总结 | 大数字 + 三项统计卡 +「完成本次复习」/「退出复习」 |

**字段定义**：`QuizData {options:[{letter,text,is_correct}], correct, explanation}`；`review_result {mistake_id, correct:bool, self_rating:1|3|5}`。

**异常处理**：AI 出题 JSON 解析失败 → 该题降级（R-7.2）；出题整体超时（>30s）→ 全部降级直接进入复习；API 无网络 → 本地 mock 出题（基于题目模板）。

**验收标准**：AC-04 出题→作答→判分→解析→自评→复习次数+1 全链路；退出进度保留。

### FR-08 复习计划

**功能描述**：基于 SM-2 算法生成每日/周度/考前复习计划，展示今日待复习题目。

**触发条件**：复习 Modal 列表视图。

**业务规则**：
- R-8.1 调度算法：SM-2，根据每次自评分数（1/3/5）计算下次复习间隔（如 陌生→1 天、模糊→3 天、掌握→7 天，含动态系数）；
- R-8.2 范围：每日 / 周度 / 考前三档；
- R-8.3 到期题目进入「今日待复习」列表，与「一键复习」共用入口。

**界面交互**：计划范围切换 + 今日题目列表（序号/摘要/待复习徽章）。

**字段定义**：`ReviewRecord {mistake_id, due_at, interval_days, ease_factor, review_count}`。

**异常处理**：无到期题目 → 显示「当前没有可复习的错题」。

**验收标准**：AC-05 按 SM-2 排期展示今日待复习列表。

### FR-09 数据看板

**功能描述**：展示学习 KPI、学科分布、录入趋势、薄弱知识点、掌握率与知识图谱，所有数据与错题本实时同步。

**触发条件**：顶部导航「数据看板」。

**业务规则**：
- R-9.1 KPI：总错题数 / 已掌握 / 待复习 / 平均复习次数；
- R-9.2 掌握判定口径（R3）：`mastery_level ≥ 4` 或复习次数 ≥ 2 → 已掌握；
- R-9.3 **实时同步**：新增/删除/编辑错题、复习自评后，KPI、环形图、柱状图、图例立即刷新（R4，`syncDashboard()`）；
- R-9.4 图表：学科分布柱状（按 `data-subject` 统计）、录入趋势折线（近 7 天）、薄弱知识点横向条形、掌握率环形（`stroke-dashoffset` 按掌握比例换算）、知识图谱（节点连线，点击提示关联错题）。

**界面交互**：顶部 KPI 卡 4 张 + 2×2 图表网格 + 全宽知识图谱；无颜色依赖（图表继承主题色变量）。

**字段定义**：`DashboardSummary {total, mastered, reviewing, todo, avg_review}`。

**异常处理**：无数据 → 图表显示空态（0 值），不报错。

**验收标准**：AC-06 复习自评后看板实时同步（无需刷新）。

### FR-10 导出

**功能描述**：用户勾选错题，导出为 PDF（中文无乱码）或 Markdown 文件下载到本地。

**触发条件**：错题集 → 操作栏「导出」。

**业务规则**：
- R-10.1 弹出选择 Modal：列出当前可见错题（checkbox + 学科标签 + 题目摘要）；
- R-10.2 支持「全选 / 反选」+ 实时「已选 N」；
- R-10.3 未选任何题时导出按钮禁用；
- R-10.4 PDF：`html2canvas` 渲染（800px 白底容器）→ `jsPDF` 生成 A4，多页自动分片，中文由浏览器原生绘制**无乱码**；
- R-10.5 Markdown：Blob + `<a download>` 触发下载，含标题/学科/知识点/题目/解析/图片 base64；
- R-10.6 文件名自动带日期 `recall-mistakes-YYYY-MM-DD.{pdf,md}`。

**界面交互**：Modal 列表勾选 →「下载为 PDF (N)」/「下载为 Markdown (N)」→ 浏览器下载。

**字段定义**：`ids[]`（所选错题 id 列表）。

**异常处理**：CDN 加载失败（离线）→ toast 提示需联网；无可见错题 → toast「当前没有可导出的错题」。

**验收标准**：AC-07 PDF 中文无乱码可分页；.md 可直接编辑。

### FR-11 AI 对话

**功能描述**：学生与 AI 多轮对话提问，AI 以解题讲解/错因分析/复习建议为主，支持一键加入错题本。

**触发条件**：顶部导航「AI 答疑」。

**业务规则**：
- R-11.1 系统提示词设定为「Recall AI 错题助手」（解题讲解、错因分析、复习建议优先）；
- R-11.2 **三级降级**（NFR-11）：前端直连激活的 Provider → 后端 `/api/chat/message` 代理 → 本地 `smartReply` mock；
- R-11.3 多轮上下文：发送时维护 `chatHistory`，切历史/新建对话重置；
- R-11.4 发送体验：Enter 发送 / Shift+Enter 换行；回复带打字动画；
- R-11.5 推荐问题 chips 一键发送；
- R-11.6 对话中的题目可「一键加入错题本」。

**界面交互**：
| 区域 | 交互 |
|---|---|
| 左栏 | 历史对话列表（选中态）+「新建对话」+ 分组（全部/置顶/收藏/已解决） |
| 右栏 | AI 头像 + 欢迎语 + 推荐 chips + 用户/AI 气泡（含代码块样式）+ 输入框 + 发送键 |

**字段定义**：`ChatMessage {role:'user'|'ai', content}`；`chatHistory[]` 上下文数组。

**异常处理**：无激活 Provider 且后端未启动 → 本地 mock 回复（不白屏）；API 超时 → 提示后重试。

**验收标准**：AC-08 发送获得回复；供应商直连生效；失败 mock 兜底。

### FR-13 消息通知

**触发条件**：顶栏铃铛点击。

**业务规则**：

- R-13.2 未读消息紫色高亮 + 铃铛红点；点击单条标记已读并**行内展开详情**（`NOTIF_CONTENTS` 字典）；

### FR-14 用户设置

**功能描述**：设置 Modal 提供常规设置、主题外观、数据与隐私、关于四个 tab。

**触发条件**：头像菜单「设置」或齿轮按钮。

**业务规则**：
- R-14.1 常规设置：自动保存复习记录（开关）、每日复习提醒（开关）、每周复习目标（5/10/15/20/30 下拉）；
- R-14.2 主题外观：主题（当前固定暗黑二次元）、界面字号（小/中/大）；
- R-14.3 数据与隐私：导出全部数据（复用导出 Modal）、清除本地缓存、**删除所有错题（不可恢复）**带二次确认；
- R-14.4 关于：版本号、技术栈说明；
- R-14.5 所有设置变更 toast「设置已保存」；开关有发光态。

**字段定义**：localStorage 键 `recall-settings`。

**验收标准**：开关/下拉可切换并持久化；危险操作二次确认。

### FR-15 模型供应商配置

**功能描述**：设置「模型供应商」tab 管理 3 个 Provider（DeepSeek/硅基流动/通义千问）的连接与激活，及视觉模型选择。

**触发条件**：设置 Modal → 模型供应商 tab（齿轮默认进入）。

**业务规则**：
- R-15.1 每个 Provider 卡片：API Key（密码框）/ Base URL / Model 输入 + 状态徽章（未配置/测试中/已连接/失败）；
- R-15.2 **测试连接**：`GET {base}/models`（OpenAI 兼容），成功 → 绿「✓ 已连接」；失败 → 红「✗ 连接失败」+ 错误消息；
- R-15.3 **只有测试通过才能激活**；激活的 Provider 存 `localStorage`（`recall-providers`），同时仅一个激活；
- R-15.4 视觉模型选择：Qwen3-VL-32B（推荐）/ DeepSeek-OCR / PaddleOCR-VL-1.5 / 自定义，存 `recall-vision-model`，供 FR-01/02 使用；
- R-15.5 视觉模型「测试」按钮：1×1 图调 chat 验证。

**字段定义**：`Provider {key, base, model, status, active, lastMsg}`。

**异常处理**：Key 为空点测试 → toast「请先填写 API Key」；余额不足 → 显示 30001 错误消息。

**验收标准**：AC-10 测试通过才可激活；视觉模型切换立即生效。

**字段定义**：`{subject, knowledge_point, question, analysis}`。

**验收标准**：AC-03 编辑保存后分类归位正确。

## 5. 界面与交互需求

### 5.1 布局规范（对齐 Design System）

| 区域 | 规范 |
|---|---|
| 顶栏 | 高 56px，sticky，白底 + 1px `#E5E5EA` 下边框 |
| 页面容器 | 最大宽 1200px 居中，padding `xxl/xl` |
| 双栏 | 左栏 240px 固定 + 右栏自适应（gap xl） |
| 卡片 | 白底 + 1px 边框 + 12px 圆角，内边距 lg |
| 按钮/输入 | 8px 圆角，高 36px；图标 14px |

### 5.2 全局交互约定

| 项 | 约定 |
|---|---|
| Toast | 底部居中，2s 自动消失，z-index 200 |
| Modal | 遮罩点击关闭（设置/编辑）；「开始复习」Modal 遮罩不关闭（防止误退） |
| Loading | 按钮级 loading（文案变化+禁用）；页面级 loading（出题中） |
| 空状态 | 虚线框 + 图标 + 文案 |
| 键盘 | 输入框 Enter 提交（发送/添加分类）；Shift+Enter 换行（聊天） |

### 5.3 响应式（NFR-08）

| 断点 | 行为 |
|---|---|
| ≥1024px | 双栏布局（侧栏 240px + 主区） |
| 768–1023px | 侧栏收窄（240→200px 或图标化） |
| <768px | 单栏；侧栏转为顶部横向滑动分类条；导航折叠 |
