---

## 0. 总体评价

产品方向正确（学生错题 + AI 识别 + 智能复习是真实刚需），信息架构四页清晰（错题集 / AI 答疑 / 数据看板 / 帮助），核心"录入→归档→复习→看板→导出"闭环**在演示层面已跑通**，且已实现四级 AI 降级、无阴影 DS、三档响应式等工程化细节。

但当前产品存在**典型的"功能过载 + 演示化"问题**：16 个 FR 全量上线，其中约 1/3 是纯演示态（通知、主题外观、知识图谱、供应商配置），对 C 端学生主场景贡献有限，反而稀释了核心体验、拉长了开发与测试成本。

---

## 1. 功能是否过多？有没有可以砍掉的功能？

### 1.1 功能盘点与分级

| 功能 | 当前状态 | 评审判定 | 理由 |
|---|---|---|---|
| 拍照录入 FR-01 | ✅ 完整 | **保留（核心）** | 第一入口，图片即题目体验好 |
| 截图录入 FR-02 | ✅ 完整 | **保留（核心）** | 与拍照共用链路，成本低 |
| 文本录入 FR-03 | ✅ 完整 | **保留（核心）** | 兜底且便宜 |
| 对话录入 FR-04 | ⚠️ 简单实现 | 🔪 **建议砍掉（合并进 AI 答疑）** | 与"AI 答疑"功能重叠，四种录入里最鸡肋；真实场景学生直接发图/文本，不会"跟 AI 聊着录入" |
| 错题本管理 FR-05 | ✅ | **保留** | 分类是核心组织方式 |
| 错题列表 FR-06 | ✅ | **保留** | 主界面 |
| 一键复习 FR-07 | ✅ | **保留（核心卖点）** | ABCD 出题+判分是差异化亮点 |
| 复习计划 FR-08 | ⚠️ Modal 内 | **保留但升级为独立页** | 计划是"复习感"的关键，Modal 太轻 |
| 数据看板 FR-09 | ✅ | **保留（核心）** | 学习反馈价值高 |
| 导出 FR-10 | ✅ | **保留** | PDF/Markdown 已完整 |
| AI 对话 FR-11 | ✅ | **保留（核心）** | 接入真实模型 |
| 帮助中心 FR-12 | ✅ | **保留但精简** | 3 张入口卡是演示态，可降为纯 FAQ |
| 消息通知 FR-13 | ⚠️ 预置静态 | 🔪 **建议砍掉（MVP）** | 无真实触达逻辑，5 条预置消息是"假功能"；学生场景通知价值低，二期接真实推送再做 |
| 用户设置 FR-14 | ⚠️ 部分演示 | ✂️ **精简** | 主题外观（暗黑固定不可切换）是死功能；保留复习提醒开关与数据管理即可 |
| 模型供应商配置 FR-15 | ✅ 完整 | 🔪 **建议隐藏（高级设置）** | 面向开发者的配置对 C 端学生无意义；应收进"高级设置"或二期开放 |
| 编辑错题 FR-16 | ✅ | **保留** | 识别纠错刚需 |

### 1.2 砍/降建议汇总

- **建议砍掉（3 个）**：对话录入 FR-04、消息通知 FR-13、帮助中心入口卡（降为纯 FAQ）
- **建议隐藏/降级（2 个）**：模型供应商配置 FR-15（收进高级设置）、主题外观（移除或做真实双主题）
- **建议合并（1 个）**：复习计划 FR-08 与一键复习 FR-07 在 UI 上合并为"复习中心"一个入口

> 砍掉后 MVP 收敛为 **10 个功能**，开发/测试成本约降 30%，核心体验更聚焦。

## 2. 页面结构是否合理？有没有缺少的页面？

### 2.1 现有结构（合理部分）

```
顶部导航：错题集 / AI答疑 / 数据看板 / 帮助  + 铃铛/齿轮/头像
├─ 错题集：侧栏分类 + 主区卡片列表（操作栏：导出/录入/复习/搜索/筛选）
├─ 录入引导页（隐形页，不入导航）
├─ AI 答疑：左历史 + 右聊天
├─ 数据看板：KPI + 4 图表 + 知识图谱
└─ 帮助中心：FAQ
Modal 层：设置 / 编辑 / 导出选择 / 复习会话 / 通知面板 / 用户菜单
```

### 2.2 结构问题与缺失页面

| 问题 | 说明 | 建议 |
|---|---|---|
| ❌ **录入引导页是"隐形页"** | 只能从错题集"录入"按钮进入，不入导航；新用户不知有此页 | 首次使用 Onboarding 引导展示 4 种录入（现在是 3 种） |
| ❌ **缺"首页/今日复习"聚合页** | 无登录后第一屏；学生打开不知道该干什么 | 增加"今日"页：待复习 N 题 + 今日计划 + 快捷录入 + 最近动态 |
| ❌ **缺"复习计划"独立页** | SM-2 计划藏在 Modal，计划感弱，无法看周/月安排 | 升级为导航页"复习计划"（日历/列表） |
| ❌ **缺"错题详情页"** | 卡片点击无大图/完整解析阅读视图，长题在卡片里被截断 | 点击卡片展开详情视图或独立页 |
| ❌ **缺"复习记录/成绩"页** | 答对率、历史复习轨迹无沉淀展示 | 看板增加"复习趋势/正确率"子视图 |
| ⚠️ **设置层级过深** | 供应商配置藏在 5 层 Modal 里，普通用户误触概率高 | 与砍功能联动：收进高级设置 |
| ⚠️ **无登录/用户体系** | 本地单机可用，但产品完整度缺一环 | MVP 可接受（本地模式），二期加账号 |

## 3. 用户流程是否完整？有没有断点？

### 3.1 核心闭环：录入 → 归档 → 复习 → 看板 → 导出

```mermaid
flowchart LR
    A[录入] --> B[AI 识别] --> C[归档卡片]
    C --> D[分类管理] --> E[复习]
    E --> F[看板同步] --> G[导出/分享]
```

### 3.2 流程断点清单

| 断点 | 说明 | 影响 | 建议 |
|---|---|---|---|
| 🔴 **录入后无"勾选导入"步骤** | PRD 承诺"AI 拆分多题 → 勾选导入"，实际直接单卡归档；一图多题场景（试卷拍照）会丢题 | 高 | 拍照识别后若 AI 返回多题，展示候选列表供勾选 |
| 🔴 **数据无持久化** | 刷新即丢，错题/复习进度全部消失 | 高 | 至少上 localStorage（错题表+分类+复习记录），代码已具备 DOM 数据源，落库成本低 |
| 🟠 **"掌握度"双口径** | 答题对错（5/1 分）与自评（陌生/模糊/掌握）两套数据并存，看板统计取其一，口径混乱 | 中 | 统一：答题结果自动映射自评档位，只存一份 mastery |
| 🟠 **看板只读不可下钻** | 图表点击无跳转，用户看到"薄弱知识点"却无法直达对应错题 | 中 | 图表元素可点击 → 跳转错题集并应用筛选 |
| 🟠 **复习出题失败体验差** | 全部降级时用户仍经历 5-10s 等待后才看到"跳过选择题" | 中 | 出题前先探测可用性；失败立即提示"已切换为解析模式" |
| 🟡 **导出后无后续动作** | 下载即止，无"分享到微信/打印"入口 | 低 | 导出成功 toast 增加"分享"提示 |
| 🟡 **通知→动作割裂** | 通知内容与设置/复习无真实跳转（演示 toast） | 低 | 砍掉通知即可消除此断点 |
| 🟡 **帮助与设置割裂** | FAQ 提到"导出格式"等，但帮助页无直达入口 | 低 | FAQ 项关联跳转对应 Modal |

### 3.3 顺畅的部分（已闭环）

- ✅ 录入（拍照/截图/文本）→ AI 识别 → 卡片归档 → 分类计数联动 → 看板同步
- ✅ 复习（ABCD 答题 → 判分 → 解析 → 自评 → 次数+1）→ 看板实时更新
- ✅ 导出（勾选 → PDF/Markdown → 下载到本地）
- ✅ AI 答疑三级降级不白屏

## 4. 哪些地方可以优化？

### 4.1 产品层面（优先）

| 优先级 | 优化项 | 说明 |
|---|---|---|
| P0 | **补本地持久化** | 数据落 localStorage，产品才"可用"而非"可演示" |
| P0 | **新增"今日"首页** | 打开即见待复习任务，提升使用粘性（对应 G2 复习完成率目标） |
| P1 | **复习计划独立成页** | SM-2 计划可视化（周历/列表/考前模式切换） |
| P1 | **统一掌握度口径** | 答题 + 自评合并为单一 mastery 数据模型，看板/复习/导出口径一致 |
| P1 | **多题勾选导入** | 拍照识别多题时候选列表勾选，兑现 PRD 承诺 |
| P2 | **图表下钻** | 看板图表可点击直达错题列表 |
| P2 | **Onboarding 引导** | 首访 3 步引导（拍照/复习/看板），降低上手门槛 |

### 4.2 体验层面

| 优化项 | 说明 |
|---|---|
| 移动端优先设计 | 学生主场景是手机拍照，卡片/按钮触控尺寸、单手操作需专项走查 |
| 空状态完善 | 全空/分类空/搜索空/复习空 4 态文案与引导统一（部分已做） |
| 复习出题进度可见 | 出题中显示"第 N/10 题生成中"，替代笼统 loading |
| 复习可暂停/续做 | 中途退出后能回到上次进度（当前退出即丢） |
| 导出格式记忆 | 记住用户上次选的 PDF/Markdown |
| 错题卡片图片懒加载 | 图片题多了以后列表性能（对应 NFR-05 万级容量） |

### 4.3 数据与埋点（为后续迭代准备）

- 埋点：录入方式分布、OCR 成功率、复习完成率、答对率、看板访问率（对应 G1-G3 指标）
- 看板增加：周复习趋势、知识点掌握热力图

## 5. 评审结论

| 维度 | 结论 |
|---|---|
| 功能 | **偏多**：建议砍 3（对话录入/通知/帮助入口卡）、隐藏 2（供应商配置/主题外观），MVP 收敛至 10 个功能 |
| 页面 | **结构合理但缺关键页**：缺"今日首页""复习计划页""错题详情页""复习记录页"；录入引导页应从隐形页转为 Onboarding 可见 |
| 流程 | **核心闭环成立但有 8 处断点**：最严重的是"无持久化"与"多题勾选导入缺失"，其次是"掌握度双口径" |
| 优化 | 优先级最高三项：本地持久化 → 今日首页 → 复习计划独立页 |

**一句话结论**：Recall 的核心设想（AI 录题 + 智能复习 + 数据反馈）成立且已具备可演示的完整闭环，但当前"什么都有"的 MVP 反而模糊了卖点——**砍掉演示态功能、补上持久化与复习计划页，才是真正的学生可用产品**。
