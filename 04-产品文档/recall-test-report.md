## 3. 发现的问题

### 🔴 严重（3 项）

| 编号 | 严重度 | 模块 | 问题描述 | 位置 |
|---|---|---|---|---|
| P1-1 | 严重 | 消息通知 | **通知详情永远显示「（暂无详情）」**。`NOTIF_CONTENTS` 字典的 key 带 emoji 前缀（如 `'🎉 欢迎使用...'`），但点击时用 `notif-title` 的 textContent（不含 emoji）去查，`NOTIF_CONTENTS[title]` 恒为 undefined → 全部落入 fallback「（暂无详情）」 | L1982-1990 |
| P1-2 | 严重 | 一键复习 | **图片题复习出题失败**。`getReviewQuestionText` 对图片题返回 `'[图片题目] '+img.src`（base64 dataURL），直接把整段 base64 塞给文本模型 prompt——模型看不到图、token 爆炸、大概率出题失败；即使成功也是瞎猜 | L1348-1352 |
| P1-3 | 严重 | AI 对话 | **多轮上下文把 system 提示词重复拼接**。`callDeepSeek` 内部 `[{role:'system'},...].concat(messages)`，而 `aiReply` 传的是已含历史消息的 `chatHistory`，直连与代理两条路都重复注入 system，部分供应商（如通义）会报「system 消息不能多于 1 条」或产生行为漂移 | L1877-1900 |

### 🟡 一般（5 项）

| 编号 | 严重度 | 模块 | 问题描述 | 位置 |
|---|---|---|---|---|
| P2-1 | 一般 | 数据看板 | **「删除所有错题」后看板不同步**：`deleteAllMistakes` 清空 `cardList` 后只调 `applyFilter()`，未调 `syncDashboard()`，KPI/环形图/柱状图保留旧值 | L2014-2020 |
| P2-2 | 一般 | 导出 | **图片题导出 PDF 不含题目图片**：`downloadPDF` 只取 `.region-q .txt`（图片题此节点是「📷 图片即题目」提示文字），未处理 `.m-img`，导出内容与界面不一致 | L1546-1553 |
| P2-3 | 一般 | 导出 | **Markdown 导出缺失但文案宣称支持**：FAQ（L852）与设置页（L1125）均写「支持 PDF / Markdown」，但 `downloadPDF` 是唯一实现，无 Markdown 分支，FR-10/AC-07 未完全满足 | L1532-1583 |
| P2-4 | 一般 | 编辑错题 | **图片题编辑异常**：编辑 Modal 预填 `region-q .txt`（即「📷 图片即题目」占位），保存后 `qd.textContent=q` 会把提示文字覆盖为用户输入，若用户未改则字段变为占位文本，且图片题无法编辑图片本身 | L1262-1293 |
| P2-5 | 一般 | AI 对话 | **无加载态与防抖**：`send` 期间输入框不禁用，连点可并发多次请求；mock 兜底场景无打字反馈区分 | L1932-1937 |

### 🟢 优化（7 项）

| 编号 | 严重度 | 模块 | 问题描述 | 位置 |
|---|---|---|---|---|
| P3-1 | 优化 | AI 对话 | 流式未实现：`aiReply` 是一次性返回，NFR-02「流式首字 <2s」未达（现为整体等待） | L1903-1917 |
| P3-2 | 优化 | 复习 | 出题 loading 提示「约需 5-10 秒」但实际可能更久，且出题阶段无法取消（只能等） | L1484-1493 |
| P3-3 | 优化 | 设置 | 「清除本地缓存」仅 toast 未真实清除 localStorage（provider/设置仍留） | L2013 |
| P3-4 | 优化 | 错题列表 | 搜索无结果时无独立空状态（仅分类筛选有），用户不易感知"已筛选但无匹配" | L1203 |
| P3-5 | 优化 | 移动端 | 侧栏删除分类按钮在 <768px 被隐藏，移动端无法删除自定义分类 | L449 |
| P3-6 | 优化 | 安全 | 视觉模型 API Key 硬编码在前端 `VISION_KEY`（L1649），生产环境泄露风险（原型可接受，需提示） | L1649 |
| P3-7 | 优化 | 代码 | `esc()` 已覆盖主要注入点（✅），但 `chatHistory` 与 DOM 内容无深度清理，长期维护需统一 sanitize 策略 | 全局 |

## 4. 修改建议

### 按优先级

| 优先级 | 问题 | 建议方案 |
|---|---|---|
| P0 | P1-1 通知详情 | 去掉 `NOTIF_CONTENTS` key 的 emoji 前缀（与 `notif-title` 一致），或按 `notif-item` 索引（`data-idx`）查字典；建议用 `data-idx` 更稳 |
| P0 | P1-2 图片题出题 | ① 优先用录入时缓存的 OCR 文本 `question`（若有）作为出题素材；② 无文本则改用**视觉模型**（复用 `ocrAndAnalyze`）先转文本再出题；③ 仍失败则走现有降级。切勿把 base64 塞进文本模型 |
| P0 | P1-3 system 重复 | `aiReply` 只维护用户/助手消息，system 由 `callDeepSeek`/`callBackend` 统一注入一次（消息数组从 user 开始）；或在 `chatHistory` 前显式拼接单一 system |
| P1 | P2-1 看板漏同步 | `deleteAllMistakes` 末尾补 `syncDashboard()`（与删除单条/编辑保持一致） |
| P1 | P2-2 导出缺图 | `downloadPDF` 增加 `.m-img` 处理：将图片 dataURL 嵌入导出 HTML `<img>`，或对图片题导出"图片 + 提示文字"双内容 |
| P1 | P2-3 Markdown 缺失 | 补 `downloadMarkdown(picks)` 分支（之前已实现过，可恢复），导出 Modal 增加格式选择（PDF / Markdown） |
| P1 | P2-4 图片题编辑 | 编辑 Modal 对图片题：题目字段显示「📷 图片即题目」且只读提示，图片提供"更换"入口；保存时保留 `.m-img` 不被覆盖 |
| P2 | P2-5 发送防抖 | `send` 中加 `sending` 标志，请求完成前禁用发送键；mock 回复也走同一 loading 态 |
| P3 | P3-1~P3-7 | 流式 SSE 迭代排期；出题阶段加「取消」；清缓存真实清理 localStorage；搜索空状态；移动端分类删除改长按或列表内删除；Key 走后端代理；统一 sanitize |

### 回归建议

修复后建议按以下用例回归（与 AC 映射）：

1. **AC-01/02**：四种录入全链路（含识别失败降级）
2. **AC-03**：分类筛选/新建/删除/编辑计数联动（含图片题编辑）
3. **AC-04**：一键复习（文字题 + 图片题 + 出题失败降级 + 退出保进度）
4. **AC-06**：看板同步（增/删/编辑/复习/删除所有）
5. **AC-07**：导出 PDF（文字题/图片题）+ Markdown
6. **AC-08**：AI 对话三级降级（直连/代理/mock）
7. **AC-13**：通知点击详情 + 全部已读

## 5. 结论

| 项 | 结论 |
|---|---|
| 功能符合性 | 13/16 功能主体通过；通知详情、图片题复习出题、Markdown 导出 3 处不达标 |
| 交互稳定性 | 主要链路可用，无阻断性崩溃；有 2 处一致性缺陷（看板漏同步、编辑图片题） |
| 布局/响应式 | 三档断点正确、无阴影规范守住，质量良好 |
| 异常处理 | 降级体系完整（AI/OCR 三级兜底），但清缓存、搜索空状态等细节欠缺 |
| AI 输出 | 文本/视觉解析健壮；图片题出题链路存在设计缺陷需重构 |

**放行建议**：修复 P0 三项（P1-1/P1-2/P1-3）后可进入联调；P1 五项建议在 MVP 发布前完成；P3 项可排迭代。
